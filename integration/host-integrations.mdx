---
title: "Host integrations"
description: "Pass host documents into Libra and handle citations without duplicating host behavior."
---

Use the host integration APIs when your product wants to suggest a document, attach files, or take ownership of citation navigation. The SDK owns the chat UI; the host owns document identity, availability decisions, and any product-specific navigation.

## Attachments

An `Attachment` is either an `ExternalDocument` or a `HostFile`:

- `ExternalDocument` points to a document on your system. Libra retrieves it by `id` and `source`.
- `HostFile` is a file your host already holds in memory, such as a `File` or `Blob` in a desktop app without its own backend. The SDK uploads it into the user's active Libra project through the chat's own upload path.

## Suggest an attachment

Pass an `Attachment` to `Libra.setSuggestedAttachment()` after the session has started. The SDK shows a suggestion chip above the chat input. The attachment, including any nested `attachments`, is added only when the user clicks the chip. A new call replaces the previous suggestion.

```ts
import { Libra, type ExternalDocument } from '@libra/sdk';

const document: ExternalDocument = {
	id: 'case-1842',
	title: 'Acme v. Northstar',
	url: 'https://host.example.com/documents/case-1842',
	source: 'wko_de',
	attachments: [
		{
			id: 'case-1842-pdf',
			title: 'Acme v. Northstar PDF',
			url: 'https://host.example.com/documents/case-1842.pdf',
			source: 'wko_de'
		}
	]
};

await Libra.setSuggestedAttachment(document);
```

The host owns the document ID and URL. `source` identifies the owning source:

- A supported research source, such as `'wko_de'`. `web_search` is not allowed.
- A legal software product (`LegalSoftwareSourceId`): `'kleos'`, `'legisway'`, `'notaionext'`, or `'suitenext'`. For these sources, `id` is the product's own document ID, and Libra starts indexing the document when it is attached.

A nested attachment uses the same shape without its own nested attachments. Availability is checked for the whole group.

Call `Libra.clearSuggestedAttachment()` when the host selection is no longer relevant:

```ts
await Libra.clearSuggestedAttachment();
```

## Attach directly

Use `Libra.addAttachments()` to attach one or more items to the current chat's chat input without a suggestion chip. Use `Libra.clearAttachments()` to remove every host-provided attachment from the chat input.

```ts
import { Libra, type HostFile } from '@libra/sdk';

// selectedFile is a File the host already holds, for example from <input type="file">.
const file: HostFile = { file: selectedFile, title: 'Engagement letter.pdf' };

await Libra.addAttachments([file]);

// Later, when the host context changes:
await Libra.clearAttachments();
```

A `HostFile` built from a `File` can omit `title`; the SDK uses `file.name`. A `HostFile` built from a `Blob` has no name of its own, so `title` is required. The title is shown on the chip and used as the uploaded file name.

All four attachment methods require an active session. Call them after `Libra.attach()` has completed. The host remains responsible for product permissions, entitlement decisions, and document URLs. Before a research document is attached, the SDK checks that it's in your FAB index; see [Availability boundary](#availability-boundary).

### Deprecated suggestion methods

`Libra.setDocumentSuggestion()` and `Libra.clearDocumentSuggestion()` still work and forward to `setSuggestedAttachment()` and `clearSuggestedAttachment()`. Each logs a one-time deprecation warning in the console. Migrate to the new methods:

| Deprecated | Replacement |
| --- | --- |
| `setDocumentSuggestion(document)` | `setSuggestedAttachment(document)` |
| `clearDocumentSuggestion()` | `clearSuggestedAttachment()` |

## Citation ownership

Register `onCitationClick` when the host can open research documents in its own viewer. The callback receives the research source, URL, and optional passage text. The SDK opens unclaimed URLs in a new tab by default.

```ts
Libra.init({
	productId: 'wko_de',
	onCitationClick: (event) => {
		if (event.data.source === 'wko_de') {
			event.preventDefault();
			hostViewer.open({
				url: event.data.url,
				selectedText: event.data.content
			});
			return;
		}

		// Leave citations owned by other sources untouched.
		// The SDK opens them in a new tab.
	}
});
```

Call `event.preventDefault()` only when the host has claimed the navigation. For citations the host does not own, leave the event untouched so the SDK keeps its default behavior. The public event data contains only `source`, `url`, and optional `content`; do not depend on staging-only fields such as `kind`. `data.url` may include a `documentAnchor` query parameter for section positioning. Citations for internal Libra workspace features do not reach this callback.

### Citation validation checklist

- Confirm the host can resolve every source it claims.
- Preserve the URL, including any document anchor.
- Use `content` as optional cited passage text, for example to scroll to it; it may be absent.
- Test both claimed and unclaimed citations.
- Verify that unclaimed citations open in a new tab and claimed citations stay in the host viewer.

## Files and storage

An `ExternalDocument` stays on your system: provide URLs that the host can resolve, and keep storage, access control, and URL lifetime in the host. A `HostFile` is uploaded into the user's active Libra project, the same way as a file the user picks in the chat.

<Note>
The public SDK does not provide a document availability-check method or a way to list or remove files that are already uploaded to a project. Keep file access and availability decisions in the host or its backend.
</Note>

## Availability boundary

Libra can use an `ExternalDocument` from a research source only if the document is indexed in your product's FAB index. The SDK checks each group, a document plus its nested `attachments`, against the index. Availability is all or nothing per group: one missing member makes the whole group unavailable.

| Method | When the check runs | If the group is unavailable |
| --- | --- | --- |
| `setSuggestedAttachment()` | In the background while the chip is visible. | Selecting the chip attaches nothing and shows a **Content unavailable** notice. |
| `addAttachments()` | Right away. The attachments show a loading state, and sending waits for the check. | The group stays in the chat input, disabled, and blocks sending until the user removes it. A notice offers **Try again** and **Remove**. |

`HostFile` entries skip the check and upload right away.

Legal software sources (`kleos`, `legisway`, `notaionext`, `suitenext`) aren't in the FAB index. Libra links the document into the active project's Chat uploads folder, indexes it, and makes it available when indexing finishes. It's disabled if the user has no connection to the product, the product isn't enabled for the team, or indexing doesn't finish within 90 seconds. A suggested legal software document is linked only when the user selects its chip.

The SDK doesn't expose these checks or their results to the host. Make sure the documents you suggest or attach are in your FAB index, keep product permissions and entitlement decisions in the host, and don't depend on the internal availability request or response shape.
