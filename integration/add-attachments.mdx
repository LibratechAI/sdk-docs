---
title: "Add attachments"
description: "Attach documents or files to the chat input without a suggestion chip, and remove them again."
---

Use `Libra.addAttachments()` to attach one or more items to the current chat input without a suggestion chip. Use `Libra.clearAttachments()` to remove every attachment your product added. See [Attachments and availability](/integration/attachments) for the attachment types.

<Tabs>
  <Tab title="Research product">
    ```ts
    import { Libra } from '@libra/sdk';

    await Libra.addAttachments([
    	{
    		id: 'case-1842',
    		title: 'Acme v. Northstar',
    		url: 'https://host.example.com/documents/case-1842',
    		source: 'wko_de'
    	}
    ]);
    ```
  </Tab>
  <Tab title="Legal software">
    ```ts
    import { Libra } from '@libra/sdk';

    await Libra.addAttachments([
    	{
    		id: '9585',
    		title: 'Kaufvertrag.pdf',
    		url: 'https://kleos.example.com/documents/9585',
    		source: 'kleos'
    	}
    ]);
    ```
  </Tab>
  <Tab title="Host file">
    ```ts
    import { Libra, type HostFile } from '@libra/sdk';

    // selectedFile is a File your product already holds, for example from <input type="file">.
    const file: HostFile = { file: selectedFile, title: 'Engagement letter.pdf' };

    await Libra.addAttachments([file]);
    ```
  </Tab>
</Tabs>

One call can mix documents and host files. Each document, with its nested `attachments`, is checked as its own group.

<Warning>
**FAB index required.** `addAttachments()` checks every research document against your product's FAB index before the user can send it. Libra doesn't add documents to the index. Legal software documents and host files are indexed by Libra instead. See [Availability boundary](/integration/attachments#availability-boundary).
</Warning>

## What the user sees

- Each research document appears in the chat input right away, in a loading state. The user can't send the message until the check finishes.
- Documents that are available become regular attachments.
- A group that's unavailable, or whose check fails, stays in the chat input as disabled attachments. Hovering shows **Content unavailable**. The **Send** button stays enabled, but selecting it shows the notice again instead of sending.
- A notice above the chat input says how many files couldn't be attached, with **Try again** (checks the failed groups again) and **Remove**. It hides after 6 seconds and appears again on the next failure.
- Documents already in the chat input are skipped. Adding a disabled document again checks it again. Entries missing a required field are ignored and logged in the console.
- A `HostFile` skips the check. It's uploaded right away into the user's active project and shows as an ordinary file while it uploads. The same rules apply as for a file the user picks: a project is required, size and type limits apply, and if document uploads are turned off for the user's account, the file isn't added. A file still queued with the same name and size isn't queued twice.
- A legal software document shows a loading state while Libra indexes it, then becomes available, or disabled if it can't be used.

## Remove attachments

Call `Libra.clearAttachments()` when the context in your product changes:

```ts
await Libra.clearAttachments();
```

It removes every document your product added, including ones the user attached from the suggestion chip and ones still being checked, and cancels a chip selection that hasn't finished. Files the user uploaded or picked stay, and sent messages don't change. Host files become regular uploads once attached, so `clearAttachments()` doesn't remove them.

To let the user decide whether to attach a document, see [Suggest an attachment](/integration/suggestions).
