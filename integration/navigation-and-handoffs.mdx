The SDK can open an existing Libra chat or start a new one in the embedded session. Product navigation outside the chat remains host-owned.

## Open a chat by ID

Call `Libra.openChatById()` after `Libra.attach()` has started the session. The SDK trims the ID and ignores an empty value.

```ts
openSavedChatButton.addEventListener('click', async () => {
	await Libra.openChatById('chat-1842');
});
```

The method sends the chat ID to the embedded Libra application, and the chat opens in the SDK window in place of the current one. The host should validate that the ID belongs to the signed-in user before presenting it as a product action.

### Reopen a chat from a main-app citation

When the main Libra app opens an eligible citation that points to your product, it adds `libraChatId=<chat ID>` to your product URL. Your page reads it, attaches the SDK, opens the chat, and can then remove the parameter:

```ts
const url = new URL(window.location.href);
const chatId = url.searchParams.get('libraChatId');

await Libra.attach('libra-panel');

if (chatId) {
	await Libra.openChatById(chatId);
	url.searchParams.delete('libraChatId');
	history.replaceState(null, '', url);
}
```

The user then sees the cited document in your product with the conversation that cited it.

## Start a new chat

By default, the SDK reopens the user's last active chat after a page reload. To show a blank chat when your page starts the SDK, set `restorePreviousChat: false` in `Libra.init()`:

```ts
Libra.init({
	productId: 'wko_de',
	restorePreviousChat: false
});
```

To reset a chat that's already loaded, for example from your own **New chat** button, call `Libra.startNewChat()`:

```ts
newChatButton.addEventListener('click', async () => {
	await Libra.startNewChat();
});
```

Call `startNewChat()` only after the chat has loaded; to start the first session blank, use `restorePreviousChat: false` instead. Libra creates the chat when the user sends the first message. `detach()` followed by `attach()` keeps the current chat in either case.

## Citation handoffs

Use `onCitationClick` when a host viewer or main application should own research-source navigation. Claim only the sources your host can resolve, and leave the rest untouched so the SDK opens them in a new tab. See [Citation ownership](/integration/citation-clicks) for the payload, example, and checklist.

## Main-app and generated-document handoffs

<Note>
The current public SDK does not provide arbitrary main-app routing, generated-document handoff callbacks, or a general navigation API. Keep those routes and controls in the host application.
</Note>

The public `0.16.0` SDK exposes `openChatById()`, `startNewChat()`, and citation interception, but it does not expose a separate main-app navigation method or generated-document handoff callback. A host that needs those flows should keep the surrounding control and navigation in its own application, then use a normal host-owned link or action.

The `ExternalDocument.url` field is the navigation target for a document chip in the chat input. It is opened by the host or by the SDK's document-chip behavior according to the product flow; an indexed legal software document opens in the Document Viewer instead. It is not a generated-document API. Do not document internal viewer messages or generated-document implementation details as supported host contracts.

## Ownership checks

- The host owns saved-chat controls and authorization for chat IDs.
- The host owns routes for product pages, document viewers, and generated documents.
- The SDK owns embedded chat navigation and the default behavior for unclaimed research citations.
- `preventDefault()` is the boundary that transfers an individual citation navigation to the host.
